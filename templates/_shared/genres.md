# ジャンル定義と選び方

10ジャンルそれぞれが何のためにあるか、迷ったときの判断基準を整理しています。

## 一覧

| # | ジャンル | ファイル名 | 一行説明 |
|---|---|---|---|
| 1 | チュートリアル/入門 | `01_tutorial.md` | 技術を初めて触る人に最初の動かし方を伝える |
| 2 | ハウツー/実装解説 | `02_howto.md` | 「Xで○○を実現する方法」を解説する |
| 3 | エラー解決 | `03_troubleshooting.md` | 詰まったエラーと、その原因・解決策を共有 |
| 4 | 環境構築 | `04_environment.md` | セットアップ手順を再現可能な形でまとめる |
| 5 | 比較/選定 | `05_comparison.md` | 複数の選択肢を観点別に比較して結論を出す |
| 6 | Tips/小ネタ集 | `06_tips.md` | 単発の小技を複数まとめて紹介する |
| 7 | 設計/アーキテクチャ | `07_architecture.md` | DB設計、システム構成、設計判断の理由を書く |
| 8 | ツール紹介 | `08_tool_introduction.md` | ライブラリ・SaaS・ツールを紹介する |
| 9 | やってみた/作ってみた | `09_tried.md` | 個人開発や技術検証のプロセスをまとめる |
| 10 | 振り返り/学習記録 | `10_retrospective.md` | 経験から学んだことを抽象化して書く |

## 迷ったときの判断フロー

```
書きたいネタは何？
├─ 特定の問題を解決した記録 → 03_troubleshooting
├─ 何かを作った／試した記録 → 09_tried
├─ 学んだことの整理 → 10_retrospective
├─ 手順を伝えたい
│   ├─ 環境構築だけ → 04_environment
│   ├─ ゼロから入門 → 01_tutorial
│   └─ 特定機能の実装 → 02_howto
├─ 何かを紹介したい
│   ├─ 単一のツール → 08_tool_introduction
│   ├─ 複数の比較 → 05_comparison
│   └─ 小ネタ複数 → 06_tips
└─ 設計の話 → 07_architecture
```

## ジャンルが被るケースの判断基準

**「Reactアプリを作ってみた」は `09_tried` か `02_howto` か？**

- 開発のプロセス・苦労・工夫を中心に書く → `09_tried`
- 特定の機能の実装手順を再現可能な形で書く → `02_howto`

**「Next.jsとRemixを比べた」は `05_comparison` か `10_retrospective` か？**

- 両方を客観的に並べて選び方を伝える → `05_comparison`
- 自分が使った経験から振り返って書く → `10_retrospective`

**「TypeScriptのTipsを10個紹介」は `06_tips` か `02_howto` か？**

- 独立した小ネタの羅列 → `06_tips`
- 「○○を実現する」という一本の流れがある → `02_howto`

### 媒体ごとの特性メモ

- **note**：技術記事の濃度より、開発体験・動機・人柄のほうが読まれる。`09`, `10` が映える
- **はてなブログ**：はてなブックマーク経由で「バズる」可能性が高い。主張のあるタイトル＋目次設計が効く。`05`, `09`, `10` が伸びやすい
- **Dev.to**：英語圏。`showdev` タグの個人開発系、`discuss` タグの比較・主張系、定番タグの定型チュートリアルが伸びる。短文の `Today I Learned` 系もOK
